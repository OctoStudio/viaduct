01 Features

Everything your config file can't do.

Built for people who live in tunnels — backend engineers, DevOps, and anyone tired of ssh -L dying in a forgotten terminal tab.

F-01

Self-healing tunnels

Forwards survive sleep/wake, Wi-Fi switches, and network blips — reconnecting with exponential backoff and a visible retry count.

F-02

Menu-bar control

Connect, stop, and search every tunnel from a single keystroke. Status lives in your menu bar — green means you're through.

F-03

1Password & agent auth

Authenticate via the 1Password SSH agent, the system agent, or a Keychain-stored passphrase. No keys in plain-text config.

F-04

Local, remote & SOCKS

Forward a port in (-L), expose one out (-R), or run a dynamic SOCKS proxy (-D) — all from one interface.

F-05

Tags & smart groups

Group by environment or project. Filter to "everything connected" or "production only" in a click — and bulk-launch a whole group.

F-06

Inspect the real command

See the exact ssh invocation Viaduct runs, copy it, and read a live log of every connect, retry, and error.

03 Security

Your private keys never leave the agent.

Viaduct never reads, copies, or stores private keys. It asks your SSH agent to authenticate on demand — exactly like the ssh binary does — and shells out to the OpenSSH already on your Mac.

  • 1Password unlocks keys with Touch ID — nothing on disk in the clear.
  • No reimplemented crypto — it drives your own trusted OpenSSH.
  • No telemetry, no account, and no custom network daemon.

05 FAQ

Questions, answered.

Q-01Does Viaduct replace OpenSSH?
No — it drives the ssh binary already installed on your Mac. There's no custom crypto and no separate daemon; Viaduct builds the right invocation, supervises the process, and shows you exactly what it ran.
Q-02How does the 1Password integration work?
Viaduct talks to whichever SSH agent you point it at via the SSH_AUTH_SOCK protocol. If that's the 1Password agent, your keys are unlocked with Touch ID at connect time and are never stored by Viaduct.
Q-03What kinds of forwarding are supported?
Local (-L), remote (-R), and dynamic SOCKS (-D) forwards, with optional ProxyJump bastions and agent forwarding. Each tunnel can bind to localhost or any interface you choose.
Q-04Does it survive sleep and Wi-Fi changes?
Yes. Viaduct watches for wake and network-change events and reconnects with exponential backoff, surfacing the retry count so you always know what's happening.
Q-05What are the system requirements?
macOS 14 Sonoma or later, on Apple Silicon or Intel. Release builds are published on GitHub Releases.
